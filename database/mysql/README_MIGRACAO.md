Ou usando `mysql -u usuario -p < 01_create_tables.sql` no terminal que tenha o cliente MySQL. Não colocar senhas no comando ou em arquivos versionados.

## Mapeamentos Oracle → MySQL
- `VARCHAR2(n)` → `VARCHAR(n)`; `NUMBER(10,2)` → `DECIMAL(10,2)`.
- `NUMBER GENERATED BY DEFAULT ON NULL AS IDENTITY` → `BIGINT AUTO_INCREMENT` (não replica a semântica exata de inserir NULL/ID manual; verificar aplicações).
- `NUMBER(4)` → `SMALLINT`; `NUMBER` nas FKs → `BIGINT`.
- `DATE` → `DATE` (Oracle DATE também comporta horário; o modelo parece usar apenas datas).
- `ON DELETE CASCADE`, `UNIQUE`, `CHECK` e PK composta preservados.
- `utf8mb4` e InnoDB. MySQL 8.0.16+ é necessário para aplicar restrições CHECK.

## Divergências no documento que exigem decisão da equipe
1. **VAGA**: modelo lógico `NOME_VAGA`, `MODELO_TRABALHO`; modelo físico `NOME`, `MODEL_TRABALHO`. Esta migração conserva **os nomes físicos** para não inventar alteração.
2. **VAGA.CNPJ** e **VAGA.NOME** são opcionais no DDL físico, embora o dicionário lógico apresente a vinculação da vaga como obrigatória. Esta versão preserva nulabilidade física; confirmar se devem ser `NOT NULL`.
3. **FORMACAO/EXPERIENCIA/HABILIDADES/ACESSIBILIDADE**: modelo lógico cita `CPF`; físico usa `ID_CANDIDATO`. Preservado o físico.
4. **C22** do catálogo de consultas menciona `Lado`, ausente no DDL. Não criamos essa coluna sem aprovação.
5. O catálogo C01–C30 descreve necessidades; **não inclui SELECTs prontos**. Devem ser implementados em tarefa posterior.


## Segurança e testes

### Segurança
- `SENHA` deve receber somente hashes fortes gerados pela aplicação, nunca senhas em texto puro.
- `CPF`, `CID`, laudos e informações de deficiência são dados sensíveis e exigem proteção adequada.
- Não utilizar dados pessoais reais nos testes.
- Implementar autenticação e controle de acesso antes de expor APIs.

### Validação realizada
- Estrutura executada no MySQL Server 8.0.46.
- As 10 tabelas foram criadas com sucesso.
- Foram identificadas 9 chaves estrangeiras.
- Os testes de integridade selecionados foram aprovados.
- O teste de exclusão em cascata retornou `formacoes_restantes = 0`.
- Evidências documentadas em `03_evidencias_testes.md`.

### Cuidados na execução
- O script de criação não contém `DROP`.
- O script não é idempotente para as tabelas.
- Executar `01_create_tables.sql` apenas uma vez em banco de desenvolvimento vazio.
